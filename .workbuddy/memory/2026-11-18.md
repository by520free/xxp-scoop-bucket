## kiri WSL 数据迁到非 C 盘（F:\WSL）
- 用户运行 kiri 向导到第 2 步「添加到 WSL」失败：硬编码执行 `wsl --import kiri C:\...\Kiri\wsl\kiri kiri-linux.tar.gz --version 2`，报错是中文被单字节写坏的乱码（kiri-win.log / setup.json 的 lastError 都不可逆）。
- 关键事实：kiri 自建名为 `kiri` 的 WSL2 distro（非复用 Ubuntu），import 路径写死 `%LOCALAPPDATA%\Kiri\wsl\kiri`，GUI 无法改。失败时该 wsl 目录是空的。
- 方案：建目录联接（junction）`C:\Users\Administrator\AppData\Local\Kiri\wsl` → `F:\WSL`（F 盘已有另一发行版 canal）。对 kiri 完全透明：它照写 C 盘路径，实际数据落到 `F:\WSL\kiri`；kiri 的 Get-WslBasePath 从 Lxss 注册表读真实路径，后续步骤/卸载逻辑不受影响。
- 注意：本机安全策略拉黑 wsl.exe / reg.exe / PowerShell-from-bash，无法实测 import；junction 用 PowerShell 工具（非 bash 调用）成功建立并验证。F:\WSL 已有 canal 目录，kiri 会落成 F:\WSL\kiri。
- **失败根因定位**：用户手动 import 报 `Wsl/Service/RegisterDistro/CreateVm/HCS/ERROR_NOT_SUPPORTED`。查证：F 盘 NTFS 健康、物理机（昂达 B460SD4）、BIOS 虚拟化/SLAT/DEP 全开、Win11 22H2 专业版；但 `Win32_ComputerSystem.HypervisorPresent = False`、vmms 服务不存在、HvHost/LxssManager 均 Stopped。稀疏 VHD 警告是附带信息非根因。
- 用户执行 `bcdedit /set hypervisorlaunchtype auto` + 重启后仍失败，`HypervisorPresent` 仍 False。**进一步查 CBS 功能包注册表（HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\Packages）发现真正根因：VirtualMachinePlatform 与 HypervisorPlatform 的正常包 CurrentState=64（仅 Staged），而对应的 `-Disabled-` 包 CurrentState=112（Installed）**，即 WSL2 必需的"虚拟机平台"功能被显式关闭。修复：管理员执行 `dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart` + `bcdedit /set hypervisorlaunchtype auto` + 重启，验证 HypervisorPresent=True。
- CBS CurrentState 速查：1=Absent、64=Staged(暂存未装)、112=Installed。Disabled 包=112 表示功能被关。免提权可读；bcdedit/dism/读 BCD hive 均需提权，本环境被拦。
